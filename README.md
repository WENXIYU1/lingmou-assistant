# 灵动视眸 / Lingmou Assistant

阶段：视线算法实验与交互路线选型，**不是已通过真人验收的眼控软件或参赛安装包**。

本版已实现本地暂停/跟踪状态、双轴增益与死区、时间相关平滑、持续动作一次触发、只允许练习事件的执行器、练习设置校验与备份。界面沿用CustomTkinter，输入为鼠标模拟特征和模拟眨眼，不采集摄像头，也不注入系统鼠标事件。

上述为默认模拟模式。新增独立的`--camera`工作区，由用户手动确认开启摄像头；五点校准、三点独立验证、停留试用及个人档案都只作用于窗口内画布，不注入系统事件。

## 摄像头适配候选版

2026-09-23新增：本机已可双击 `启动新算法实验.cmd` 打开OpenVINO头姿与视线模型实验画布，或执行 `.\.venv\Scripts\python.exe -m apps.desktop --gaze-experiment`。须手动确认摄像头；完成五点训练、三点选型、另一组三点最终验收，才可在画布试用。实验模式不复用/保存档案，真人戴镜精度待验收。详见[新算法实验使用与验收](docs/新算法实验使用与验收.md)。

MobileGaze整脸方向实验可双击 `启动整脸方向短测.cmd`。真人戴镜对照表明模型能区分左右/上下方向，但中心漂移和点内波动仍不足以支持可靠像素级鼠标；稳定裁剪和简单头动线性补偿均未在独立数据上得到整体改善，当前不采用。下一阶段计划实现粗区域定位与二次放大确认，尚未完成。详见[MobileGaze方向短测](docs/MobileGaze方向短测.md)和[当前进度](docs/当前进度_2026-09-23.md)。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-vision-lock.txt
.\.venv\Scripts\python.exe -m scripts.fetch_model
.\.venv\Scripts\python.exe -m apps.desktop --camera
```

开发环境已安装依赖及校验后的模型，无需重复下载。应用不会自动下载或开启摄像头。官方模型下载地址可能受国内网络影响；当前安装好的模型可离线推理，正式交付前另行完成许可和国内资源分发审查，不依赖评委临时访问境外站点。

流程：填写本人别名 → 开启本地摄像头并确认 → 等待“双眼可用” → 开始五点校准 → 自动进入三点独立验证 → 明确开始试用 → 注视3个大目标 → 确认保存。Esc可暂停，关闭摄像头释放设备。窗口位置/大小/显示缩放属于映射环境，校准后不要移动或缩放窗口。

参数变化需要重新独立验证；切换人、摄像头或窗口环境不能复用旧结论。加载本人档案后仍需三点快速验证。设备编号不是永久硬件ID，设备更换时修改设备标记并重新校准。

**当前限制**：双眼均可用、单人、正面且相对稳定姿态；不保证覆盖特殊眼部条件。质量下降会暂停画布试用，恢复后需明确启用，频繁短眨可能带来较多暂停，需要真人测试后优化。没有原始画面预览/录制，环境检查依据特征质量提示。验证门槛是试验参数，不是已验证的精度指标。

个人档案位于本地用户数据目录`LingmouAssistant/profiles/`，含校准特征系数和设备信息，不含原始人脸图像；它仍属于个人使用数据，不应公开。普通模拟模式参数与个人校准档案分开。

详细步骤及待验收项见[第二步验证报告](docs/第二步视觉校准报告.md)。

## 运行

建议Python 3.12，Windows环境。核心无第三方依赖，界面依赖见固定版本清单。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-ui.txt
.\.venv\Scripts\python.exe -m apps.desktop --check
.\.venv\Scripts\python.exe -m apps.desktop
```

练习界面不代表五点校准。恢复后首个有效样本重新对齐中心；移动鼠标模拟输入，大目标命中次数仅用于调试，不是眼控准确率。离开画布只保持模拟位置，便于点击控制按钮；用“模拟丢失”按钮测试信号中断，恢复信号后仍需明确启用。Esc和暂停按钮只影响本程序。

```powershell
python -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m scripts.ui_smoke
```

练习参数保存在用户本地数据目录的`LingmouAssistant/practice-settings.json`；不代表用户校准档案。损坏配置不会自动覆盖，保存前需用户处理原文件。
