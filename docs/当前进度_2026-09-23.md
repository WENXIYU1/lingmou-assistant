# 灵动视眸当前进度（2026-09-23）

关联需求：REPO-01、SAFE-01、CAL-01、CAL-02、EYE-01、UI-01、DATA-01。本文记录开发状态，不是比赛作品验收或真实精度声明。

## 已实现

- 私有 GitHub 仓库与独立开发分支；源码、依赖清单、开发规则及自动测试在仓库内维护。
- Windows 本地摄像头眼部特征采集；用户明确开启摄像头，默认不录制或上传原始画面。可单独确认打开临时眼部裁剪预览；可查看采集质量审计和头部舒适位置参考。
- 首次适配流程包含五点训练、三点候选选型、另一组三点最终验收、安全画布试用及用户确认后保存个人档案。主动暂停、跟踪丢失、环境变化或验收失败时保持系统级控制锁定。
- 会话内定位诊断、上下短测，以及双眼平均与左眼纵向混合映射候选。100/150/200 毫秒因果窗口仅用于已选候选的本地处理。旧映射档案因版本变更而不兼容。

## 验证现状

- 2026-09-23 在本机运行 `python -m unittest discover -s tests`：104 项通过，均为自动/合成数据测试；此前无真实摄像头的模拟界面流程和布局检查通过。
- 用户最近一次真人戴镜五点训练：全部候选未达到训练质量门槛；双眼平均最差点中位误差 14.99%，混合候选 100/150/200 毫秒分别为 10.45%、12.98%、13.45%，实验门槛为 ≤10%。流程停止在训练阶段，未进入候选选型或最终验收。
- 此结果说明当前方案尚不能满足真实用户的稳定眼控要求，不能作为功能验收或比赛最终演示精度证明。用户此前的中线短测显示纵向信号存在，但不足以证明全屏定位精度。

## 待办与限制

1. 修正短测与混合映射启动阶段的预热规则差异，复核暂停及掉帧后滤波历史清空；更正诊断文案中仍称“当前映射v2”和“三点验证不参与自动选择”的过时表述。此项已定位，尚未完成代码修复。
2. 重新研究视线特征和映射方法，重点评估头部俯仰/侧转补偿、横纵耦合、眼镜反光和重复中心漂移；在新算法与旧算法之间做同条件对照。尚未实现新算法。
3. 再采集真人戴镜数据完成独立验收，并测量目标选择成功率及手感延迟。真实系统级控制仍未开放。
4. 联网后端、DeepSeek API、离线语音、本地小模型、应用操作、PDF 工作流和 Windows 安装包仍属后续阶段，当前仓库不提供这些交付能力。
