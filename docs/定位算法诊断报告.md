# 定位算法诊断与候选对照

2026-09-22。需求 CAL-01/EYE-01/UI-01/DATA-01；已获用户批准。范围是诊断，不是精准度修复声明；当前控制映射和10%/18%门槛未改。

## 实现

- FeatureFrame新增可选left_eye/right_eye字段，仅携带已计算的两个眼部局部坐标；原双眼平均features不变，旧映射和档案格式不变，不增加原始图像传输或保存。
- 新增MappingDiagnostics：五点结束时分别用平均、左眼、右眼训练相同仿射模型，记录每个训练点的中位/最大误差、横纵绝对误差中位数、带符号偏移。训练指标使用全部有效采样帧，不只统计拟合保留的中心点。
- 三点验证仅调用已有候选，不重新拟合、不自动挑选或激活候选。各模型沿用相同误差门槛；主流程通过与否仍只由原映射决定。
- 逐点记录头部相对确认基准的中位变化和最大绝对变化：摄像头归一化中心X/Y、脸部尺度比例、倾斜弧度、侧转代理。这些不是精确物理距离或完整三维姿态，也不能单独解释误差原因。
- “查看定位诊断（暂停采样）”打开可滚动的大字只读窗口，先暂停采样/试用；关闭不会自动恢复。报告为打开时的快照，无自动保存/上传。旧档案、旧截图没有分眼数据，明确显示缺失，不补造数据。
- 保留原有修改；未推送、合并、发布或访问真实摄像头。

## 结论与限制

已验证诊断能识别合成的训练失配、验证偏移、单眼退化等情况，不能据此证明真人误差来源或候选模型更好。当前没有采集新版真人数据，未运行真人精度测试；不会要求用户立即重复校准。需要后续一次经用户同意的完整会话才能产生新的分眼对照证据；同一轮五点/三点即可评测三个候选，不必各做一轮。

五个点不适合无约束堆叠高维参数，此轮没有新增高维头部回归或多项式模型。若根据这轮验证结果选定新映射，必须再用新的独立位置/会话评估，不能把选型结果当最终验收。诊断窗口实际DPI视觉布局、真人舒适度仍未验收。
