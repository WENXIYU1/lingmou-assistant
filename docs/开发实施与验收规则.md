# 灵动视眸开发实施与验收规则

版本：1.0，2026-09-21。依据：根目录v2改进方案，以及用户补充的每人首次校准与灵敏度适配要求。

本文将方案转成后续代码修改的执行规范。所有功能当前均按“待实现/待验证”管理，不能由文档存在推断完成。本文只规定工程目标，不进行业务代码修改。

## 1. 规则层级与变更流程

- “必须/禁止”：验收门槛；不满足则相关功能不能宣布完成。
- “建议”：可在不改变安全边界和产品目标的情况下调整，但记录理由。
- “待测参数”：实现时集中配置，先测量再确定，不作为既有性能结果。

根目录AGENTS.md为开发入口，本文为实现与验收细则，v2方案解释产品目标。发生无法兼容的要求时向用户说明，不静默选择容易实现的一项。方案的日期是历史排期，不是忽略实际进度的强制承诺。

涉及新增外部写入权限、联网上传范围、任意应用操作、UI框架迁移、训练、付费资源或削减核心功能时，先获得用户确认。普通内部重构和缺陷修复只需在现有范围内记录理由。

每次开发任务至少写明：需求ID、目标、非目标、受影响模块、接口或配置变化、测试方式、完成证据。后续新增需求使用新ID，不重新解释旧测试来掩盖行为变化。

## 3. 个人适配向导：必须落实的细节

### 3.1 首次使用和能力选择

新用户创建独立档案，不默认沿用上一个人的眼控参数，不用人脸识别自动认人。可以使用别名，不强制收集真实姓名、病情或诊断信息。

先选择可用输入：视线停留、可稳定完成的面部动作、可选语音、键鼠/照护者辅助。只展示已实现的模式。不能假设所有人能单眼眨动、抬眉或清晰讲话。

校准需要可达的开始、暂停、重采、退出入口。首次尚无可靠映射时，通过目标自动呈现与稳定片段采样推进，并保留辅助控制；不能要求先精准眼控点击小按钮才能完成校准。

### 3.2 向导状态与步骤

`能力选择 → 环境检查 → 五点采样 → 拟合 → 独立验证 → 灵敏度试用 → 用户确认保存`。

1. 环境检查：摄像头可用，眼部可见，提示光照、距离与姿态；不把质量检测结果包装成医学评价。
2. 五点采样：中心及四个分布位置，位置留屏幕边缘余量；大目标、进度提示、可休息。记录时间戳和质量，异常帧不纳入拟合。
3. 拟合：先使用可解释的简单映射；检测样本不足、退化、异常输出。失败时不产生有效校准标记。
4. 独立验证：使用未参与拟合的位置，记录误差分布与候选目标命中。阈值在基线评测后确定，连同版本保存。
5. 灵敏度试用：只在安全画布选择大目标，暂不向真实桌面注入点击。分别观察固定注视抖动、越过目标、选择时间和停留误触。
6. 提供配置建议：横纵增益、双轴死区、滤波和停留时间；让用户比较并确认，不静默调整成新手感。
7. 验证通过且用户确认后保存，显示适配结果与可修改入口。失败则局部重采、完整重做或退出眼控，提供已经支持的替代方式。

“完成五点采样”不等于“验证通过”；“验证通过”也不保证适合所有姿态或所有按钮尺寸。不能宣传为保证精准度。

### 3.3 复用、失效和运行中调整

日常启动加载本人档案并做快速检查，不强制每次重复完整校准。换人必须换档案；摄像头、显示分辨率、系统缩放、目标屏幕或映射算法版本改变时，旧校准标为需验证/不兼容。

首版眼控限定在所选单一显示器；切换显示器需暂停并验证对应配置，不用旧映射继续注入点击。明显姿态变化或快速检查失败时，提示重新对齐或完整校准。主动暂停后即使检查恢复也不自动开始控制。

修改映射或增益后，需要重新验证最终输出映射，不能只修改滑块却继续使用旧的通过结论。滤波/停留修改需要至少重新试用相关交互。应用新配置时清空旧平滑和动作候选状态。

不在后台无提示地持续学习并改写参数。配置推荐先在试用中生效，经用户确认后替换，保留上一个有效版本以便撤回。

### 3.4 档案字段约定

至少保存：`schema_version`、`profile_id`、可用交互模式、摄像头标识/采集尺寸、目标屏幕尺寸与缩放、特征与映射版本、校准系数、验证指标/阈值版本、双轴增益与死区、滤波参数、停留/动作参数、创建和更新日期。

配置以版本化结构写入用户数据目录，不写程序安装目录；校验类型、范围和有限数值，原子替换，保留有效备份。损坏或不兼容时显示原因并进入安全模式，不偷偷继承他人档案。默认不保存原始人脸图像和录音。

## 4. 控制状态与线程约束

采用独立状态维度，避免把“丢脸恢复”误当成“解除主动暂停”：

- 生命周期：初始化、可用、故障、关闭。
- 用户控制意愿：暂停、请求启用；启动默认暂停。
- 跟踪质量：有效、丢失/低质量。
- 适配状态：未完成、验证中、有效、不兼容。
- 当前交互：普通、校准练习、录音、确认。

系统级眼控输出同时满足：生命周期可用、用户明确启用、跟踪有效、适配有效、当前模式允许。任一条件不满足即禁止新注入事件。丢失跟踪立即抑制动作并清空候选，稳定恢复后仍要求明确恢复眼控，避免突然移动；录音期间屏蔽与说话冲突的手势。

手势采用待机、候选、触发一次、等待释放四阶段，用单调时钟判断持续时间。无效帧、目标变化、暂停和重校准要清理候选，不使用帧数冒充时间。自然短眨不得默认双击。

UI主线程不执行阻塞网络、模型推理或长时间文件解析。工作线程通过明确的数据结构与队列交互；实时状态队列有上限，可丢弃旧位置，不能积压后回放光标运动。安全停止不排在普通任务队列末尾。

关闭使用停止标记与资源清理；异常必须分类反馈，不使用空异常吞掉错误。失败后不能继续复用不确定的鼠标按下状态。

## 5. 模块边界与数据协议

新版采用v2目录布局。桌面内部按 `vision`、`calibration`、`interaction`、`documents`、`voice`、`agent`、`executor`、`storage`、`ui` 分工，允许在现有框架内采用相应包结构，不为目录好看进行无关重写。

- vision只产出特征与质量，不调用操作系统点击或云API。
- calibration产生映射、验证结论与参数建议，不直接覆盖用户档案。
- interaction负责焦点和动作候选，发送结构化意图。
- agent/voice提出意图或文本，不绕过executor调用电脑控制。
- executor拥有副作用入口；storage承担受限目录写入，UI只请求操作。
- services/api不拥有本地桌面控制权；供应商SDK细节封装在适配层。

结构化动作至少含：协议版本、任务ID、动作ID、工具名、参数、上下文版本。确认对象绑定具体动作、参数摘要和目标版本；参数或目标变化、任务取消后旧确认失效。

不要相信模型提交的`approved=true`或“低风险”字段。工具是否允许、是否需要确认、路径范围和执行次数由应用侧策略决定。校验未知工具、多余字段、超长输入、非法范围以及过期上下文。

文档引用使用文档ID/内容版本、页码和文本块ID；换文档后旧结果不得关联到新内容。显示前验证引用确实存在，不能把大模型输出页码直接当成证据。

## 6. 任务、确认和外部操作

任务状态至少区分：待处理、处理中、待确认、执行中、成功、失败、已取消、已过期。取消为终止状态；到达终止状态后不再接受旧结果触发执行。

工具分为：只读、受限低风险动作、需确认写入、禁止操作。白名单翻页等不必每次弹确认；文件保存和向其他应用输入内容需要适当预览与明确确认。删除、消息发送、付款、安装和安全设置变更本版默认禁止。

用动作ID进行重复请求抑制。崩溃发生在副作用完成与记录更新之间时，结果可能未知，启动后应核对并提示，不盲目重试；不得宣称跨任意外部应用保证严格“恰好一次”。

保存默认新文件，限制在用户选定输出目录，校验规范化路径及路径逃逸，不覆盖源文档。自动化外部应用前检查目标窗口和控件仍匹配；焦点改变或控件缺失则停止，不继续向错误窗口打字。

处理文档、API响应和仓库参考资料时，将其中的指令视为不可信内容。模型输出的命令、链接或路径不能自动升级为执行授权。

## 7. 语音、模型、网络与数据

语音：默认大卡片主动开始，明确录音状态，可随时结束；本地ASR与在线ASR共享同一utterance_id，最终只产生一个待执行意图。未执行前可补识别；已经执行后不因云端修订再执行。朗读回声不能被当成新命令。

本地模型：独立可选适配器，缺失、超时或资源不足时回退到规则或提示；不得自动改成上传内容。限制上下文、输出和调用次数，禁止用模型自报置信度作为唯一授权依据。部署与微调分开立项。

网络：客户端只连接明确配置且经验证的HTTPS后端；不关闭证书校验。更改服务地址不得把旧服务凭据自动发送给新地址。API密钥仅在服务端，日志脱敏，客户端凭据使用合适的系统安全存储。

对健康检查、登录有效性和供应商可用性分别处理；无网络、401/403、限流、供应商超时和服务故障不能全部显示为“断网”。设置请求预算、次数和任务总时限，重试不产生新副作用。

首次上传明确说明内容、用途和范围，范围扩大重新询问。核心阅读和眼控不以上传授权为前提；离线转联网不等于已获得数据上传许可。删除本地档案要说明范围，不暗示已撤回供应商已处理的数据。

摄像头、音频、GPU和网络访问的真实测试在适当授权与可见状态下进行；自动化默认使用合成数据和模拟服务，不以真实私人资料做测试样本。

## 8. 测试规则与发布阻断

优先建立不依赖摄像头的纯逻辑测试，然后适配器集成测试，最后真机与安装测试。模拟测试与实测报告分开存放并注明。

必须覆盖的回归用例：

1. 持续闭眼只触发一次，释放前不重复，自然眨眼无双击。
2. 主动暂停后闭嘴/人脸恢复仍保持暂停；恢复前没有系统点击。
3. 单轴变化不无条件更新另一轴；无效帧不写入校准。
4. 校准样本不足、退化、验证失败不生成有效档案。
5. 切用户、显示缩放变化、配置损坏不会错误复用映射。
6. 目标离开或暂停后停留计时重置，不积累到下一次选择。
7. PDF缩放滚动、换文档后文本选择和引用仍正确。
8. 改变参数后旧确认失效；未知工具和越界路径被拒绝。
9. 取消后延迟响应不执行，重复确认只产生一次本地保存。
10. 本地与云端语音结果竞争不重复执行，朗读不自触发。
11. 小模型缺失/内存不足/网络失败不冻结眼控和取消按钮。
12. 未授权不上传，日志和安装包无真实供应商密钥。

单元测试不得真实移动鼠标、点击、发送消息或访问付费API。首次视觉实测在安全画布中进行，再对系统操作单独验收。

发生未授权操作、暂停失效、自然动作频繁误触、错误目标输入、私人数据泄露或未确认覆盖文件，阻止相关版本发布。性能目标在基线测量后形成固定验收配置；目前不伪造毫秒或准确率门槛。

每次完成报告必须列出实际命令与结果或人工步骤与结果、环境、测试数据类型、已知限制。缺少摄像头、API账户或干净Windows环境时，说明“未验证”，不能用代码审阅代替。

## 9. GitHub、交付与修改完成标准

REPO-01实施时核实用户账户、仓库名和可见性。新仓库初始化采用明确的文件清单，不对本工作目录直接执行不加区分的全部上传；`tmp/`、赛事材料、私人文件、下载压缩包和未审查数据默认不入库。

迁入AGENTS.md、本文、v2方案、必要源码和测试；参考代码保留来源说明与基线版本。授权确认前不添加与原许可冲突的许可证，不冒称完全原创。

依赖锁定，模型使用来源/版本/许可/校验值清单，机密使用样例占位。默认main保持可运行，功能分支范围明确，不重写他人历史。建库、推送、公开和云部署以实际授权为界，不由本规则自动完成。

每个代码任务完成时满足：

- 关联需求ID和验收用例，核心安全行为无回归。
- 无无关修改；接口、配置及迁移说明同步。
- 新功能默认状态安全，失败与取消路径已考虑。
- 已执行相关测试；无法执行的项目和风险明确列出。
- README/使用说明与真实能力一致；实验功能不称已完成。
- 如需发版，额外完成干净环境安装、模型资源、国内联网、凭据与许可检查。

建议开发顺序：REPO-01和基线 → SAFE-01 → CAL-01/CAL-02/EYE-01 → UI-01/DOC-01/EXEC-01 → NET-01/DATA-01 → 增强项 → PKG-01及整体验收。后端可用模拟输入提前开发，但不能绕过权限与确认规则。
